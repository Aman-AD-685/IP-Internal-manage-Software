## Checklist page — Filter by User fix
- **Issue:** Admin "Filter by User" / "All Users" did not change the task list; dropdown showed All Users but data stayed on logged-in user.
- **Root cause:** Frontend `effectiveUserId = selectedUserId ?? user?.id` so All Users never omitted `user_id`; Ant Design Select `value: undefined` unreliable. Backend forced `user_id = auth["id"]` for admins when param omitted.
- **Fix:** `CHECKLIST_ALL_USERS` sentinel on frontend; `resolveChecklistApiUserId()` omits API param for all users; reload on `selectedUserId` change. Backend admin endpoints skip doer filter when `user_id` absent; `_checklist_occurrences_for_user` accepts optional `user_id`.
- **Files:** `fms-frontend/src/pages/Task/ChecklistPage.tsx`, `backend/app/main.py`

## Dashboard KPI — merged week (week 5) wrong checklist %
- **Issue:** June week 5 (merged 29 Jun–5 Jul) showed wrong weekly checklist % and pending/completed counts for all users; weeks 1–4 OK.
- **Root cause:** Completions and NA marks were loaded only for the selected calendar month; July 1–5 portion of merged week was treated as never completed.
- **Fix:** `_fetch_checklist_completions_map`, `_kpi_checklist_completion_span`; week stats use full Mon–Sun range; Support FMS ticket fetch spans merged week; cache bump `dash:kpi:v3` / `dashboardKpi:v3`.
- **Files:** `backend/app/main.py`, `fms-frontend/src/api/dashboardKpi.ts`
