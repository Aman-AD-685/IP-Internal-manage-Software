## Bug: CH-0672 in DB but missing from Register of Tickets

**Symptom:** Ticket `CH-0672` visible in Supabase (`status_4=completed`) but not on Register of Tickets (Status=Completed, Type=Chores). Chores & Bugs also empty for it (expected if solution form already submitted).

**Root cause:** `GET /tickets?section=register-of-tickets&register_status_filter=completed` required `status_1 = 'yes'` AND `status_4 = completed`. The common workflow is First Action **No** (`status_1='no'`) then Stage 2→4; those tickets never matched Register Completed. Only the First Action Yes shortcut path appeared (e.g. CH-0550 range).

**Fix:** `backend/app/main.py` — Register Completed = `quality_solution` present + `status_4` completed; drop `status_1=yes`; still exclude `status_2=rejected`.

**Verify in Supabase (optional):**
```sql
select reference_no, status_1, status_2, status_4, quality_solution is not null as has_solution
from public.tickets where reference_no = 'CH-0672';
```
